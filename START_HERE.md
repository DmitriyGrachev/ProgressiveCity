# Progress City — передача задачи Codex

Это пакет задания и настроек, **не готовое приложение**. Код создаст агент по промту. Исходная концепция сохранена в `docs/CONCEPT.md` без изменений.

## Что сделать

1. Распакуй папку в удобное место на компьютере, например `C:\Projects\ProgressCity`. Имя внешней папки произвольное. В корне должны находиться `AGENTS.md`, `.codex/`, `docs/` и `prompts/`, а не ещё одна случайная вложенная копия проекта.
2. Для новой папки можно выполнить `git init` — это создание локального репозитория, не коммит и не публикация. При существующем проекте не заменяй файлы без сравнения. Особенно не перезаписывай свои `AGENTS.md` и `.codex/config.toml` вслепую.
3. Ознакомься с `.codex/config.toml` и `docs/CODEX_SETTINGS.md`. Открой именно этот проект в локальном Codex, подтверди доверие только к своей папке. Войди через ChatGPT и выбери Astra / High, если они доступны. При отсутствии Astra используй Sol / High, заменив строку model на `gpt-5.6-sol` либо выбрав модель в текущей задаче.
4. Начни новую задачу в режиме с редактированием файлов. Вставь короткое сообщение ниже или весь `prompts/START_CODEX.md`. Не нужно вставлять все файлы в чат: агент прочитает их из папки.
5. Штатно одобряй нужные проекту скачивания зависимостей/браузера; не отключай sandbox ради удобства. Агент должен сам реализовать проект и запустить проверки. Git commit, push и публикация ему запрещены.

## Короткое первое сообщение

```text
Прочитай AGENTS.md, docs/MVP_SCOPE.md, docs/CONCEPT.md и prompts/START_CODEX.md.
Выполни задание из prompts/START_CODEX.md: реализуй и проверь рабочий MVP,
а не только макет или план. Продуктовое направление уже согласовано.
Работай по этапам, фиксируй решения и фактический статус в docs/STATUS.md.
Не проси повторно одобрять обычные обратимые решения; необходимые
разрешения на установку и действия вне workspace запрашивай штатно.
Не коммить, не пушь, не создавай PR и не деплой: я сделаю это сам.
В конце передай инструкции запуска, результаты проверок, ограничения
и docs/REVIEW_REPORT.md.
```

## Если работа прервалась

Новая задача в этой же папке:

```text
Прочитай AGENTS.md, docs/MVP_SCOPE.md, prompts/START_CODEX.md,
docs/IMPLEMENTATION_PLAN.md и docs/STATUS.md, если последние уже созданы.
Сначала сверь их с фактическим кодом и git status. Продолжи незавершённые
этапы без переписывания уже работающих частей. Сохрани запрет на коммит,
push и деплой. Подтверди результат реальными проверками.
```

## Перед GitHub

Запусти приложение по README, который создаст агент. Сам выполни один реальный сценарий: заметка с изображением → подтверждение → улучшение → перезагрузка → поиск → экспорт. Восстановление сначала проверь в отдельном тестовом профиле, а не поверх единственной личной копии.

Для независимого прохода открой новую задачу с `prompts/REVIEW_BEFORE_GITHUB.md`. После проверки закоммить код, lockfile, инструкции и отчёт. Не коммить node_modules, личные архивы города, реальные заметки, токены и auth.json. `.gitignore` включает базовые исключения, но не заменяет проверку подготовленного diff.

Для дальнейшего ревью передавай ссылку на репозиторий и SHA коммита; отчёт с проверками должен находиться в репозитории. Скриншоты для публичного ревью — только с синтетическими данными.

## Содержимое комплекта

- `AGENTS.md` — постоянные правила разработки и проверки.
- `.codex/config.toml` — проектная конфигурация Codex.
- `.gitignore` — стартовые исключения из Git.
- `docs/CONCEPT.md` — исходная концепция v0.1.
- `docs/MVP_SCOPE.md` — уточнённые границы первой реализации.
- `docs/CODEX_SETTINGS.md` — модель, reasoning, права, Windows и источники.
- `prompts/START_CODEX.md` — полное задание на реализацию.
- `prompts/REVIEW_BEFORE_GITHUB.md` — независимое ревью без правок.

README приложения, исходный код, тесты и отчёты создаются агентом. Файлы пакета не утверждают, что приложение уже реализовано или протестировано.
