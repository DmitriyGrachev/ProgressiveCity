# Архитектура и принятые решения

## Границы

Один локальный frontend, одна Dexie/IndexedDB база `progress-city-v1`. React отображает панели, Zustand хранит только выбор панели/инструмента, PixiJS 8 рисует город через WebGL. Сервер Vite не получает пользовательские материалы. Git-репозиторий при реализации не создавался.

- `src/domain`: типы, календарная дата, правила наград, изометрические преобразования и пересечения прямоугольников; без React/PixiJS.
- `src/storage/db.ts`: схема v1 и согласованное чтение в транзакции. `service.ts`: команды, валидация, транзакции.
- `src/city`: императивная интеграция PixiJS с жизненным циклом React. Собственная локальная векторная архитектура. Камера и pointer-preview живут вне React; постоянная запись — только после подтверждённого размещения.
- `src/notes`: общая установленная схема Tiptap/ProseMirror, runtime node view для изображений и последовательная SaveSession.
- `src/features`: направления, результаты, библиотека, строительство, районы, история и настройки.
- `src/storage/backup.ts`, `validation.ts`: ZIP-формат, ограниченная распаковка, проверки схемы/ссылок и атомарная замена.

## Модель и инварианты

Таблицы v1: cities, tracks, buildings, districts, notes, attachments, activities, events, snapshots, metadata. Стабильные UUID не зависят от координат. Уникальный индекс buildings.trackId исключает второе здание одного направления. Свободный декор не имеет trackId. Баланс и этап хранятся у направления, снятие здания удаляет только размещение.

Подтверждение в одной `rw`-транзакции читает актуальную запись, проверяет детерминированный event ID, отмечает подтверждение, изменяет баланс и добавляет событие. Для занятия ключ `activity:<id>`, для привычки `habit:<trackId>:<local-date>`. Конкурирующие вкладки сериализуются IndexedDB. Повторная команда улучшения имеет ключ `upgrade:<commandId>`. Событие хранит величину и версию правила; расходы отрицательные, декоративные события нулевые. Нехватка баланса и ошибка записи откатывают всю транзакцию.

Дата привычки вычисляется Intl.DateTimeFormat в выбранной IANA-зоне, а не обрезкой UTC. Date/track/timezone закрепляются при первом сохранении. Награда при отсутствии отметки достижения равна нулю; никакие честные записи не снимают прошлые очки. Полный пересчёт намеренно не реализован.

Снимки — самостоятельные структурированные копии зданий со stage, районов и времени. Они создаются при старте, после улучшения и вручную. История использует тот же renderer и камеру; изменение исторической планировки заблокировано. При открытии заметок видно, что это текущие материалы.

## Заметки и сохранение

Источник заметки — Tiptap JSON. Поисковый текст выводится из него при записи. Одна SaveSession на редактор сохраняет последовательно, включая изменения, пришедшие во время предыдущей записи. Переходы ждут flush; на время перехода прежняя запись недоступна для ввода. Загрузка изображения также завершается перед переходом. Ошибки оставляют draft и показывают ошибку; навигация не выбрасывает несохранённый текст.

Ревизия заметки проверяется в транзакции. Конфликт не перезаписывает чужую версию: отдельная копия создаётся атомарно и открывается после фиксации. `metadata.epoch` меняется при восстановлении архива и блокирует запись старой редакторской сессии даже при совпадении импортированной revision. Это внутренняя метка БД, не часть архива. Blob URL существует только в node view, освобождается при размонтировании/смене epoch и не сохраняется в JSON.

Изображения хранятся как Blob со стабильными attachmentId. Разрешены PNG/JPEG/WebP ≤5 MiB, проверяется сигнатура. Схема заметки не принимает произвольный HTML, удалённые image URL, скрипты или код к исполнению. URL допускаются только http/https/mailto. Импорт проверяет JSON и через allowlist, и через **ту же ProseMirror schema.nodeFromJSON().check()**, которую использует редактор. Неизвестная структура не заменяется молча пустым документом.

## Резервный архив v1

`.progresscity.zip`: `manifest.json` с format/version/exportedAt и списком файлов, размерами и SHA-256; `data.json` с сущностями и метаданными вложений; `attachments/<id>` с исходными байтами. SHA-256 обнаруживает повреждения, не является подписью или шифрованием. Экспорт читает все таблицы в согласованной транзакции; Blob обрабатываются после её завершения.

Лимиты: ZIP 64 MiB, суммарная распаковка 128 MiB, manifest 1 MiB, data 32 MiB, одно изображение 5 MiB; до 1002 файлов. Распаковка fflate идёт кусками с контролем реально выдаваемого объёма, имён и дубликатов. Разрешены только два JSON-пути и `attachments/<safe-id>`. Типы/размеры/контрольные суммы/связи/геометрия/журнал проверяются до замены. Наличие события проверяется в обе стороны, баланс сверяется с журналом. Один импорт не начисляет новые награды.

Максимумы формата: 1000 направлений, 1600 размещений, 200 районов, 5000 заметок, 1000 вложений, 20 000 активностей, 50 000 событий, 1000 снимков. До 20 000 узлов и 30 уровней в заметке. Формат предназначен для небольшого личного города; приложение явно отклоняет экспорт за пределами лимитов без изменения базы.

Подтверждённая замена очищает/заполняет таблицы в одной транзакции. Ошибка ввода или IndexedDB оставляет прежнюю БД. Со стартового экрана можно импортировать без создания временного города. Существующий город заменяется через настройки после подтверждения и предложения экспорта. Перед будущей миграцией: добавить `db.version(2).stores(...).upgrade(...)`, отдельную миграцию формата архива и тест старой фикстуры; не менять незаметно значение manifest.version.

## Версии и официальные источники

Node 24.19.0, npm 12.0.2. Точные версии — package.json/package-lock.json. React 19 + Tiptap 3 проверены по peer dependencies; Vite 8 + plugin-react 6 совместимы; Vitest 5 допускает Node 24. PixiJS 8 подключён напрямую, без риска несовместимости @pixi/react.

Проверены [Vite — Getting started](https://vite.dev/guide/), [PixiJS 8 — Application](https://pixijs.com/8.x/guides/components/application), [Tiptap — React](https://tiptap.dev/docs/editor/getting-started/install/react), [Dexie — transactions](https://dexie.org/docs/Dexie/Dexie.transaction()). При реализации дополнительно читались типы и исходники установленных PixiJS, Tiptap/ProseMirror и fflate.

## Рисунки и визуальный выбор

`src/city/art.ts` и иллюстрация стартового экрана — собственные векторные рисунки, без коммерческих игровых ассетов, внешних шрифтов и генерации концепт-арта. Светлая оболочка, зелёная карта, фиксированная боковая навигация и одна контекстная панель. Карта и ввод работают локально. Скриншоты в review-evidence содержат только синтетические результаты; галерея из девяти зданий — тестовая фикстура, не стартовый город и не пользовательский деморежим.
