# Полная продуктовая итерация A–D — план исполнения

Прямое поручение пользователя: после завершения текущих пунктов1–3 полностью реализовать [PRODUCT_DIRECTION_AND_ROADMAP](PRODUCT_DIRECTION_AND_ROADMAP.md). Этот документ фиксирует дизайн до кода; перечисленное ниже пока не является готовыми функциями. Один исполнитель, независимые обзоры только чтение. Без новых зависимостей, backend, AI, новой валюты, PR или деплоя. Личный origin5173 и профиль не используются для тестов.

## Подтверждённые решения

- Новая привычка: фиксированная награда3 по умолчанию, настраиваемая в её правиле. Старые привычки сохраняют explore/verify/apply и прежние суммы до явного перехода. Нулевая подтверждённая дата остаётся окончательной, смена правила её не награждает повторно.
- Проект финансируется одним направлением. До первого взноса выбор свободный; после взноса очки остаются в проекте, его можно отложить/продолжить. Возврат не добавляется. Расход, вклад и event сохраняются атомарно. Undo отменяет только геометрию.
- Существующие исследования, дома привычек, оплаченные дополнения, заметки, изображения и прошлые снимки сохраняют ID/баланс/вид. Новая модель проекта не подменяет LearningObject или старый immutable purchase event.

## A — привычка строит квартал

1. Выбор первого типа направления в существующем onboarding; одна стартовая постройка, без выдуманного прошлого. В короткой новой привычке видимы цель, фиксированное правило и явное подтверждение. Текст необязателен; автоматически составляется только описание подтверждённой даты/цели, не выдуманный опыт. Для reduce сохраняется самостоятельная оценка пользователя.
2. Версионированное optional `Track.habitRule`, фактический режим/версия/сумма в event. Отсутствие поля означает прежние правила. Явная команда перехода старой привычки, без пересчёта событий. Прежний ключ `habit:trackId:date` остаётся защитой даты.
3. Ограниченная `CityProject`: постоянный ID, один trackId, каталог/тема, зафиксированная цена, внесённая сумма, состояние отложен/активен. Отдельная таблица проектов и immutable contribution events; геометрия ссылается на projectId. Выбрать и разместить план можно до stage3. Вклад явно ограничен текущим балансом и остатком цены; retry идемпотентен. После первого взноса тип/источник/цена закреплены; отложить и снять с карты можно.
4. Небольшой каталог из нескольких разных силуэтов, три согласованных темы, доступных любой привычке. Базовая цена опирается на constructionCost3; более крупные проекты имеют явно показанные кратные цены как гипотезу пилота. Старые парк/площадь/дерево и три архитектуры остаются. Изображение карточки/preview/карты использует один art source/cache.
5. Визуальные стадии стройки отражают только сохранённый вклад; они не означают учебный этап владельца. В панели — внесено/цена, следующий шаг, реальные источники и записи. Snapshot сохраняет собственные стадию и вклад; A/B сопоставляет по projectId и остаётся read-only.
6. Аддитивная БД4 без переписывания старых строк; явный ZIP4 со строгими readers1/2/3. Новые массивы/поля проходят прежние byte budgets и полную проверку ссылок/журнала. Старый импорт дополняется только пустыми новыми сущностями. Проверки7/30/90 синтетических дат, пробелов и нулевых дней.

Read-only дизайн-обзор до реализации уточнил обязательные проверки:

- Старый `version(2).upgrade` должен использовать замороженный validation-v2/profile2; актуальная v4-схема с обязательным массивом проектов не должна ломать миграцию1→2. Импорт сначала строго проверяет исходную версию, затем явно конвертирует в4.
- При подтверждении сравнивается правило, показанное формой, включая восстановленный ввод. Правило другой вкладки не подменяет обещанную награду. Повтор уже сохранённой даты показывает фактическое прежнее событие.
- Взнос нельзя назначать `PendingForm.save`: «Сохранить и продолжить» не финансирует проект. Финансовая кнопка отдельная. Связанный последний результат не объявляется единственным источником всего общего баланса направления.
- Снимок хранит собственный paid/total/вид; A/B отмечает изменение вклада даже без перехода визуальной стадии. Исторический вид не вычисляется из сегодняшней настройки проекта.
- Предлагаемые новые силуэты: оранжерея, творческая студия, обсерватория; три темы общие для всех привычек. Проверить реальные preview/ghost/map и читаемость при отдалении.

## B — связный квартал

- Чистая функция соседей дороги задаёт окончания/прямые/повороты/перекрёстки. Снимок берёт собственные дороги. Данные существующих клеток не меняются.
- Производное примыкание участка к соседней дороге: только оформление, без блокировки наград или финансирования.
- Существующий прямоугольный District рисуется, перемещается и изменяется мышью с preview; Escape не пишет. Один жест — одна прежняя команда layout/undo. Числовые поля и optimistic conflict сохраняются.
- Три набора оформления: preview показывает точный список предлагаемых изменений; прежнее индивидуальное оформление включается только явно. Один атомарный layout command с проверкой исходных полей и одной отменой. Никакой тихой перезаписи пользовательского цвета.
- Проверка плотного квартала, удалённых районов, подписи/камера/narrow и исторические дороги A/B.

## C — несколько месяцев

- Пользователь явно выбирает следующую стройку/особый объект как ближайшую цель. Город остаётся главным экраном, управление опирается на существующую панель.
- Накопительные достижения выводятся из сохранённых событий и не требуют непрерывной серии; пропуск не отменяет заработанного. Без новых наград за открытие экрана.
- Явный переход от первого собственного снимка к текущему через прежний A/B с историческими данными. Не новый статистический дашборд.
- Синтетические30/90 дней проверяют дальнейший выбор и цену. Настоящий короткий пилот отмечается NOT_RUN до реального использования человеком; удержание не объявляется доказанным.
- Расширение40×40 выполняется только при доказанном упоре содержательной застройки в границы. При отсутствии такого условия фиксируется N/A, без лишней миграции координат.

## D — живое место

Необязательные прохожие по имеющимся дорогам, спокойное движение растений, освещение и экспорт фото города. Визуальные актёры ограничены по количеству, не имеют экономики и сохраняемых «жителей». В фоне движение/лишний render останавливаются, reduced motion соблюдается. Один renderer; фото — его обычный экспорт. Проверить включение/выключение, фон, снимки/A-B и измерить ресурсы.

Кадр косметической анимации не должен вызывать текущую DOM-раскладку CityLabels: подписи пересчитываются по камере/выбору/наведению/размеру, Pixi-кадр — отдельно. Фото не включает DOM-подписи и незавершённый инструмент; это явно обозначается рядом с действием.

Установка для внешнего распространения, CI и лицензия условны: пользователь пока не поручал выпуск другим людям и не выбирал лицензию. Не придумывать это решение. Локальные Prepare/Start/Stop и понятное резервирование остаются обязательны.
